## 🤖 ما هو Brainstorming-Plus؟

Brainstorming-Plus هو شريك تفكير رفيع المستوى — يتناوب بين دور **ميسّر التصميم**، و**المراجع الأول**، و**شريك التحدي النقدي**. على عكس أدوات التنفيذ البسيطة، تهدف هذه المهارة إلى دفعك نحو أقصى حدودك، وتقديم زوايا نظر غير متوقعة، ومساعدتك على الوصول إلى أفكار لم تكن لتصل إليها بمفردك.

تُحوّل هذه المهارة مساعد الذكاء الاصطناعي الخاص بك (Codex، OpenCode، Claude، إلخ) إلى شريك استراتيجي أول يمنع التسرع في الاستنتاج، ويتحدى الفرضيات المعيبة، ويرشدك عبر مراحل معرفية منظمة.

### 🧠 المنطق والفلسفة

يقوم المنطق الأساسي لهذه المهارة على **التفاعل المنظم** و**الرأي الحازم**:

| المبدأ | الوصف |
|--------|-------|
| **شريك، لا بنّاء** | المهارة لا تكتب أكواداً ولا تعدّل سلوكيات خلال مرحلة التفكير؛ تركز حصرياً على التصميم والتحقق الفكري. |
| **التناقض البنّاء** | مصممة لتحدي افتراضاتك ("هذا يفترض X — هل نحن متأكدون من ذلك؟") ومنع التقارب المبكر نحو حل. |
| **التباعد قبل التقارب** | تشجع على استكشاف خيارات متعددة قبل الاستقرار على اختيار نهائي. |

### 🎯 الأهداف

- تحويل الأفكار الخام إلى **مواصفات مُتحقق منها** عبر حوار منظم.
- تجنب المزالق الشائعة (Anti-patterns) مثل تطوير حلول قبل تعريف المشكلة، أو فخ التكافؤ الوظيفي مع المنافسة.
- ضمان وضوح مشترك حول **"ماذا"** و**"لماذا"** و**"لمن"** قبل كتابة سطر واحد من الكود.
- ضمان **الصرامة التقنية** عبر دمج المتطلبات غير الوظيفية (الأداء، القابلية للتوسع، الأمان) بشكل منهجي.

## 🎯 متى تستخدم هذه المهارة؟

✅ التفكير في مشكلة أو توليد/تحسين الأفكار
✅ تحدي افتراض أو موازنة المقايضات
✅ التخطيط لمشروع أو ميزة أو مبادرة استراتيجية
✅ معالجة قرار غامض أو مفتوح النهايات
✅ الحصول على رأي ثانٍ أو الخروج من حلقة فكرية مغلقة
✅ هيكلة قرار (خيارات ← مخاطر ← مقايضات ← خطوات تالية)

### أوضاع العصف الذهني التكيفية

تكيّف المهارة سلوكها حسب حالة تفكيرك:

| الوضع | متى |
|-------|-----|
| **استكشاف المشكلة** | المشكلة لم تُعرَّف بعد |
| **توليد الحلول** | المشكلة واضحة لكنها تحتاج أفكاراً متباعدة |
| **اختبار الفرضيات** | الضغط على اتجاه تم اختياره مسبقاً |
| **الاستكشاف الاستراتيجي** | قرارات طويلة المدى وتحديد المواقع |

## 🚫 متى لا تستخدمها؟

❌ البحث عن حقائق بسيطة
❌ توليد أكواد مباشر بمواصفات واضحة
❌ مهام تتطلب فقط تنفيذ خطة معتمدة مسبقاً

## 📦 التثبيت الشامل (Global Installation)

بما أن مهارات وكلاء الذكاء الاصطناعي قد توحدت حول صيغة `SKILL.md`، يمكنك تثبيت Brainstorming-Plus بشكل شامل ليكون متاحاً في **جميع** مستودعاتك ومشاريعك.

### الخيار 1: سجل `skills.sh` (موصى به)

```bash
npx skills add habibfarhat/brainstorming-plus --global
```

### الخيار 2: التثبيت اليدوي

انسخ هذا المستودع إلى دليل المهارات الشامل لوكيلك:

| الوكيل / المنصة | دليل المهارات الشامل |
| :--- | :--- |
| **OpenAI Codex CLI** | `~/.agents/skills/brainstorming-plus/` |
| **OpenCode** | `~/.config/opencode/skills/brainstorming-plus/` |
| **Claude Code** | `~/.claude/skills/brainstorming-plus/` |

```bash
# أمر bash شامل للتثبيت
git clone https://github.com/habibfarhat/brainstorming-plus.git /tmp/brainstorming-plus

# لـ Codex CLI
cp -r /tmp/brainstorming-plus ~/.agents/skills/

# لـ OpenCode
cp -r /tmp/brainstorming-plus ~/.config/opencode/skills/

# لـ Claude Code
cp -r /tmp/brainstorming-plus ~/.claude/skills/
```

## 🏗️ البنية الأساسية

يُحكم Brainstorming-Plus V2 بواسطة **طبقتين مستقلتين ومتفاعلتين**:

| الطبقة | الدور | السؤال |
|--------|-------|--------|
| **طبقة الحوكمة** | هيكل العملية: التأطير، التوضيح السقراطي، قفل الفهم، البدائل، المقايضات، سجل القرار، التسليم | *أين نحن في العملية؟* |
| **المحرك المعرفي** | الذكاء التكيفي: يختار التدخل المعرفي الأنسب تالياً | *أي نوع من التفكير يجب أن يحدث الآن؟* |

### محاور التحكم الثلاثة

| المحور | السؤال | القيم |
|--------|--------|-------|
| **حالة العملية** | أين نحن؟ | Frame → Explore → Ideate → Evaluate → Decide → Handoff |
| **العدسة المعرفية** | كيف نفكر؟ | Expand → Challenge → Transform → Reframe → Connect → Stress-test → Execute |
| **وضع التحكم** | من يختار؟ | AUTO → GUIDED → MANUAL |

### حالات العملية (آلة حالات محكومة)

العملية هي **آلة حالات محكومة بحلقات خاضعة للرقابة**، وليست تسلسلاً خطياً صارماً:

```
Frame → Explore → Ideate → Evaluate → Decide
                                         │
                                         │ موافقة المستخدم
                                         ▼
                                      Handoff
                                         │
                                         │ إذن التنفيذ
                                         ▼
                                   التنفيذ الفعلي
```

### العدسات المعرفية السبع

| العدسة | السؤال المحوري | أمثلة على التقنيات |
|--------|---------------|-------------------|
| 🔍 **Expand** | "ماذا يمكن أن يكون هذا أيضاً؟" | Starbursting، Brainwriting، القياس |
| ⚔️ **Challenge** | "هل تفكيرنا خاطئ؟" | محامي الشيطان، اختبار الافتراضات |
| 🔧 **Transform** | "كيف نغيّر هذا؟" | SCAMPER، الطرح، المبالغة |
| 🔄 **Reframe** | "ماذا لو كانت المشكلة مختلفة؟" | الأسباب الخمسة، Jobs-to-be-Done |
| 🔗 **Connect** | "ماذا يحدث عندما تتصادم هذه؟" | المصفوفة المورفولوجية، الاندماج |
| 🧪 **Stress-test** | "هل ينجو من الواقع؟" | Pre-mortem، الحالات الحدية |
| 🚀 **Execute** | "كيف نحوّل هذا إلى عمل؟" | التفكيك، المسار الحرج، MVP |

> 📖 المرجع الكامل: [references/REFERENCE.md](references/REFERENCE.md)

### الأدوات والأطر المتاحة

حسب الحاجة، تستخدم المهارة أدوات تفكير منظمة مثل:

- **Jobs-to-be-Done (JTBD)** — فهم الدوافع العميقة للمستخدمين.
- **SCAMPER** — تحويل منتج أو فكرة موجودة.
- **حلقة OODA** — اتخاذ قرارات سريعة في بيئات تنافسية.
- **العصف الذهني المعكوس** — تحديد المخاطر عبر تخيّل كيفية إفشال المشروع.
- **Pre-mortem** — افتراض الفشل الكامل وتتبّع الأسباب.
- **الأسباب الخمسة** — تتبّع السبب الجذري للمشكلة.

## ⚙️ أوضاع التحكم

| الوضع | السلوك |
|-------|--------|
| **AUTO** (افتراضي) | الذكاء الاصطناعي يختار العدسة المعرفية بناءً على إشارات التشخيص |
| **GUIDED** | الذكاء الاصطناعي يوصي بـ 2–3 عدسات؛ أنت تختار |
| **MANUAL** | أنت تختار التقنية صراحةً؛ الذكاء الاصطناعي يطبّقها |

## 📊 مقياس التعقيد

| المستوى | النوع | المخرجات |
|---------|-------|---------|
| **A — دقيق** | قرارات سريعة، قابلة للتراجع | مشكلة ← خيارات ← توصية |
| **B — قياسي** | تعقيد متوسط | تأطير ← افتراضات ← 2–3 مقاربات ← مقايضات |
| **C — معقد** | أصحاب مصلحة متعددون | قفل الفهم ← NFRs ← مقاربات ← سجل القرار |
| **D — تحولي** | تأثير مؤسسي، غير قابل للتراجع | وثيقة تصميم كاملة ← تحليل سيناريوهات ← خارطة طريق |

## 🔑 القاعدة الذهبية: فصل العدسة عن المرحلة

> **عدسة Execute تُهيكل كيفية تحويل اتجاه مقبول إلى عمل. إنها لا تُصرّح بالتنفيذ الفعلي.**

| المفهوم | المعنى | هل يمكن إنتاج أكواد؟ |
|---------|--------|---------------------|
| **عدسة Execute** | التفكير في كيفية تحويل اتجاه مقبول إلى فعل | ❌ لا |
| **Handoff** | تغليف التصميم المعتمد للتنفيذ | 📦 مخرجات جاهزة للتنفيذ |
| **التنفيذ الفعلي** | الانتقال من التفكير/التصميم إلى البناء | ✅ نعم، بإذن صريح |

## 🚦 معايير الخروج

تعتبر المهارة الجلسة مكتملة فقط عندما:

- ✅ التصميم أو القرار مُطوَّر بما فيه الكفاية ومُعتمد.
- ✅ المخاطر مُعترف بها.
- ✅ **سجل القرار** (Decision Log) مُنشأ عند الاقتضاء.
- ✅ أوجه عدم اليقين غير المحلولة مُحددة صراحةً.
- ✅ المستخدم لديه خطوات تالية واضحة أو Handoff مُعرَّف.
